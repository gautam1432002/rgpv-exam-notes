Q1. Define Cloud Computing. Explain the Characteristics of Cloud Computing. 🔥 POPULAR
— OR —
Q1B. Describe the characteristics of a cloud computing environment.
7 Marks10 Marks
Definition

Cloud Computing is a model for enabling on-demand, ubiquitous network access to a shared pool of configurable computing resources (networks, servers, storage, applications, and services) that can be rapidly provisioned and released with minimal management effort or service provider interaction.

NIST Definition (remember for exam): "Cloud computing is a model for enabling convenient, on-demand network access to a shared pool of configurable computing resources that can be rapidly provisioned and released with minimal management effort or service provider interaction." — NIST SP 800-145
5 Essential Characteristics (NIST Model)
Cloud Computing Characteristics
1. On-Demand Self-Service
2. Broad Network Access
3. Resource Pooling (Multi-tenancy)
4. Rapid Elasticity
5. Measured Service (Pay-per-use)
  • On-Demand Self-Service: A user can provision resources (CPU, storage) automatically without human interaction with the service provider. Example: Launching an AWS EC2 instance in minutes.
  • Broad Network Access: Services are available over the network and accessible from diverse devices — laptops, mobiles, tablets. Uses standard internet protocols.
  • Resource Pooling (Multi-tenancy): Provider's resources serve multiple consumers using a multi-tenant model. Resources are dynamically assigned based on demand. Users don't know exact physical location.
  • Rapid Elasticity: Capabilities can be quickly scaled up/down (elastic) according to demand. To the user, resources appear unlimited and can be purchased at any time.
  • Measured Service: Resource usage is monitored, controlled, and reported (pay-per-use). Billing is based on actual usage — like electricity billing.
Additional Characteristics
  • High Availability & Reliability: Cloud providers guarantee uptime (SLA — 99.9% or 99.99%).
  • Scalability: Resources scale horizontally (more machines) or vertically (bigger machine).
  • Cost Efficiency: Pay-as-you-go eliminates capital expenditure on hardware.
  • Location Independence: Access from anywhere with internet connection.
⭐

Always write the NIST 5 characteristics. Draw a diagram. This question is asked every year! Keyword: On-Demand, Broad Access, Resource Pooling, Elasticity, Measured Service (mnemonic: OBREM).

✏️ Cloud computing revolutionizes IT by converting capital expenditure into operational expenditure, providing scalable, reliable, and cost-effective computing resources accessible anywhere over the internet.

Definition — SOA

Service Oriented Architecture (SOA) is a software design paradigm where application components provide services to other components through well-defined interfaces (called service contracts) over a network. Each service is an independent, reusable, and loosely-coupled software component.

Simple Understanding: SOA is like a restaurant — you (service consumer) order food from a menu (service contract). The kitchen (service provider) prepares it. You don't care HOW it's made, only WHAT you receive. Services communicate using standard protocols (SOAP/HTTP/REST).

  • Service Provider: Defines and publishes services with a service contract (WSDL).
  • Service Registry (UDDI): A directory where providers publish service descriptions. Consumers search here.
  • Service Consumer: Discovers services in UDDI and invokes them using SOAP/REST messages.
Key Principles of SOA
  • Loose Coupling: Services are independent — changes in one don't break others.
  • Interoperability: Services communicate using platform-independent protocols (HTTP, XML, JSON).
  • Reusability: A single service can be used by multiple applications.
  • Abstraction: Internal logic is hidden; only the interface is exposed.
  • Discoverability: Services can be found and used dynamically via UDDI.
  • Composability: Multiple services can be composed into complex business workflows.
How SOA Supports Cloud Computing
  • SOA's service-based model directly maps to cloud service models: SaaS, PaaS, IaaS are all services.
  • Cloud exposes infrastructure as services (IaaS), platforms as services (PaaS) — SOA principles enable this.
  • Interoperability between different cloud providers is achieved using SOA's standard protocols (REST/SOAP).
  • Loose coupling allows individual cloud services to evolve without affecting consumers.
  • Service registries (like UDDI) help in service discovery in cloud environments.
⭐

✏️ SOA forms the backbone of cloud computing by enabling services to be developed, published, discovered, and consumed independently — making cloud service models (SaaS, PaaS, IaaS) possible through standardized, loosely-coupled service interfaces.

Web Services — Introduction

A Web Service is a software system designed to support interoperable machine-to-machine interaction over a network. Web services use standard protocols (HTTP, XML, SOAP) to communicate between applications on different platforms.

1. SOAP — Simple Object Access Protocol

SOAP is an XML-based messaging protocol used for exchanging structured information between web services over HTTP/HTTPS. It is the communication layer of web services.

SOAP Message = Envelope + Header (optional) + Body + Fault (optional)
  • Envelope: Root element — defines start and end of SOAP message.
  • Header: Contains optional metadata (security tokens, session info).
  • Body: The actual message payload — the request or response data.
  • Fault: Error information if processing fails.
  • Transport: SOAP runs over HTTP, HTTPS, SMTP. It is platform-independent.
  • Example: An e-commerce website calling a payment gateway using SOAP to process a payment.
2. WSDL — Web Services Description Language

WSDL is an XML-based language that describes the interface of a web service — what operations it provides, what parameters they take, and how to invoke them. It is the service contract.

  • Types: Data type definitions used by the service (XML Schema).
  • Messages: Input and output message definitions for each operation.
  • Port Type: Set of operations (methods) provided by the service.
  • Binding: Defines the protocol and message format for each operation (SOAP binding).
  • Service: Specifies the endpoint (URL) where the service can be accessed.
  • Role: WSDL answers — WHAT the service does, HOW to call it, WHERE it is.
3. UDDI — Universal Description, Discovery, and Integration

UDDI is an XML-based directory (registry) for web services that allows businesses to publish service information and discover each other's services. It is like a yellow pages for web services.

Elements of UDDI
  • White Pages: Business contact information — name, address, phone number, unique business identifier (DUNS number).
  • Yellow Pages: Business categorization — industry type, product/service type using NAICS/UNSPSC codes. Allows search by category.
  • Green Pages: Technical service information — how to invoke the service (WSDL URL, binding information, access points).

Q5. Explain RESTful Services — Definition, Characteristics, Components and Types. 🔥 POPULAR
5 Marks7 Marks
Definition — REST

REST (Representational State Transfer) is an architectural style for designing networked applications. RESTful services use HTTP methods to perform CRUD operations on resources identified by URLs. It is simpler and lighter than SOAP.

REST vs SOAP: SOAP is heavy (XML envelope, strict protocol), REST is lightweight (can use JSON, uses plain HTTP). REST is preferred for mobile apps and modern microservices.
Characteristics of REST
  • Stateless: Each request from client contains ALL information needed. Server stores NO client session state.
  • Client-Server: Clear separation between UI (client) and data storage (server). Independent evolution.
  • Cacheable: Responses can be cached by client to improve performance.
  • Uniform Interface: Standard HTTP methods (GET, POST, PUT, DELETE) used for all resources.
  • Layered System: Client doesn't know whether it's communicating directly with server or a proxy.
  • Code on Demand (optional): Server can send executable code (JavaScript) to client.

Cloud Monitoring — Introduction

Cloud Monitoring is the process of reviewing, observing, and managing the operational workflow in a cloud-based IT infrastructure. It involves collecting metrics, logs, and performance data to ensure services are running optimally.

Key Areas of Cloud Monitoring
  • Infrastructure Monitoring: CPU usage, memory, disk I/O, network bandwidth of VMs and physical servers.
  • Application Performance Monitoring (APM): Response time, error rates, throughput of cloud applications.
  • Database Monitoring: Query performance, connection pool usage, replication lag.
  • Security Monitoring: Intrusion detection, unauthorized access attempts, firewall logs.
  • Cost Monitoring: Track resource usage and optimize billing. AWS Cost Explorer, Azure Cost Management.
Tools: AWS CloudWatch, Azure Monitor, Nagios, Zabbix. Cloud Administration Tasks
  • User and role management (IAM — Identity and Access Management).

  • Managing SLAs (Service Level Agreements) and compliance.
  • Backup and disaster recovery management.
  • Patch management and software updates.
  • Auto-scaling policies — scale up/down based on load.

Q7. Differentiate between Utility Computing and Elastic Computing. 🔥 POPULAR
5 Marks7 Marks
Utility Computing — Definition

Utility Computing is a pay-per-use computing model where computing resources (CPU, storage, bandwidth) are provided as a metered service — just like electricity, water, or telephone utilities. Users pay only for what they consume.

Example: Amazon Web Services charges per-hour for EC2 instances. You pay ₹5 per hour only for the hours you use the server. Like paying electricity bill — pay for kWh consumed.
  • Resources provisioned on-demand, metered, and billed accordingly.
  • No upfront investment (CAPEX → OPEX model).
  • Focuses on economic model of computing delivery.
  • Examples: AWS, Azure, Google Cloud (all billing services).
Elastic Computing — Definition

Elastic Computing is a cloud computing model that automatically scales computing resources up or down based on workload demand — without manual intervention. It ensures resources always match the current load.

Example: An e-commerce website automatically gets 100 servers during a sale (Diwali), then scales back to 10 servers after the sale. AWS Auto Scaling Group does this automatically.
  • Resources scale elastically (up/down) based on demand.
  • Prevents over-provisioning (wasting money) and under-provisioning (performance issues).
  • Focuses on technical capability of dynamic scaling.
  • Examples: AWS Auto Scaling, Azure Scale Sets, Google Managed Instance Groups.

Virtualization — Definition

Virtualization is the process of creating a virtual (software-based) version of a physical resource — including servers, storage, networks, or operating systems. Multiple virtual machines (VMs) run simultaneously on a single physical machine.

Virtualization Architecture
Virtualization Architecture
VM1 (Windows)

Hypervisor (VMM) — VMware ESXi / Hyper-V / KVM

Physical Hardware (Real CPU, RAM, NIC, Storage)
Types of Virtualization
  • Server Virtualization: Multiple VMs on one physical server. Most common in cloud (IaaS).
  • Storage Virtualization: Multiple physical storage devices pooled into a single virtual storage unit (SAN, NAS).
  • Network Virtualization: Software-defined networks — multiple virtual networks on one physical network (VLAN, SDN).
  • Desktop Virtualization (VDI): Desktop environments hosted on a central server, accessed remotely. Example: Citrix, VMware Horizon.
  • Application Virtualization: Apps run in isolated containers without installation. Example: Docker containers.
Hardware Virtualization Techniques
  • Full Virtualization: VM completely simulates hardware. Guest OS runs unmodified. Slower due to binary translation. Example: VMware Workstation.
  • Para-virtualization: Guest OS is modified to know it's running in a VM. More efficient. Example: Xen para-virtualization.
  • Hardware-Assisted Virtualization: CPU hardware (Intel VT-x, AMD-V) directly supports virtualization — fastest. Example: KVM, VMware ESXi.
  • OS-Level Virtualization (Containers): Shares host OS kernel, isolated user space. Lightest weight. Example: Docker, LXC.
Benefits of Virtualization
  • Server consolidation — fewer physical servers needed, reduced hardware cost.
  • Better resource utilization — physical server's resources fully used.
  • Isolation — VMs are isolated; failure of one doesn't affect others.
  • Disaster recovery — VM snapshots allow quick recovery.
  • Fast provisioning — deploy new servers in minutes (spin up a VM).
  • Testing & development — test on multiple OS without extra hardware.
Pitfalls of Virtualization
  • Performance Overhead: Hypervisor consumes CPU/RAM — VMs run slower than bare metal.
  • VM Sprawl: Too many VMs created, leading to management challenges and wasted resources.
  • Security Risks: Hypervisor vulnerabilities can compromise all VMs (VM escape attacks).
  • Complexity: Managing hundreds of VMs, snapshots, and virtual networks is complex.
  • Licensing Costs: Commercial hypervisors (VMware vSphere) are expensive.
  • Single Point of Failure: If the hypervisor crashes, all VMs on that host go down.
  • Network Issues: Virtual networking can create complex routing and latency problems.
⭐

Draw the virtualization architecture diagram. "Pitfalls" question — write exactly 5-6 pitfalls with bold headings. Mention: VM sprawl, hypervisor overhead, VM escape, vendor lock-in. Very common 7-mark question.

✏️ Virtualization is the foundational technology of cloud computing — enabling resource sharing, isolation, and rapid provisioning. Despite pitfalls like performance overhead and security risks, its benefits in cost savings and flexibility far outweigh the drawbacks.

Q9. What is Multitenant Software? Explain Multi-tenancy techniques and risks in cloud. 🔥 POPULAR

Multi-tenant Software — Definition

Multi-tenant software is a software architecture where a single instance of an application serves multiple customers (tenants). Each tenant's data is isolated and invisible to other tenants, but they share the same application and infrastructure.

Analogy: Multi-tenancy is like an apartment building — all residents (tenants) share the building (software), but each has their own private apartment (data). They don't see each other's belongings.
Multi-tenancy Approaches
  • 1. Multi-Entity Support (Single DB, Shared Tables): All tenants' data in ONE database with ONE set of tables. A "tenant_id" column distinguishes tenant data. Simple but risk of data leakage if not properly filtered.
  • 2. Multi-Schema Approach: Single database, but SEPARATE schema (set of tables) for each tenant. Better isolation. Example: Tenant A → schema_A.customers, Tenant B → schema_B.customers.
  • 3. Separate Database per Tenant: Each tenant has their OWN database instance. Maximum isolation and security. Most expensive approach. Best for sensitive data (healthcare, banking).

Risks of Multi-tenancy
  • Data Leakage: Bug in tenant filtering logic can expose Tenant A's data to Tenant B.
  • Noisy Neighbor Problem: One tenant consuming excessive resources degrades performance for all.
  • Compliance Issues: Regulated industries (healthcare, banking) may not allow shared infrastructure.
  • Security Breaches: A vulnerability in one tenant's app can potentially affect others sharing the same instance.
  • Limited Customization: Tenants cannot deeply customize the shared application.

Cloud Mashup — Definition

A Cloud Mashup is a web application that combines data, functionality, or presentation from two or more cloud-based services into a single integrated experience. Mashups aggregate multiple APIs to create new, useful services.

Example: Google Maps API + Weather API + Local Business API = A single app showing weather forecasts for businesses on a map. Each API is from a different service provider.
Need for Cloud Mashups
  • Combine best-of-breed services from different providers.
  • Rapid development — no need to build everything from scratch.
  • Cost effective — use existing APIs rather than developing functionality.
  • Innovation — creative combinations create new value-added services.
  • Business agility — quickly respond to market needs by combining services.
Types of Mashups
  • Consumer Mashups: Combine public APIs for end users. Example: Travel apps combining flights (Skyscanner) + hotels (Booking.com) + maps (Google Maps).
  • Business/Enterprise Mashups: Combine internal enterprise data with external cloud services. Example: CRM data + social media data.
  • Data Mashups: Combine data from different sources and represent it as a single database. Example: Twitter + LinkedIn data for recruitment analytics.
— AJAX (Part 2) —
AJAX — Asynchronous JavaScript and XML

AJAX is a web development technique that allows web pages to update data asynchronously by exchanging small amounts of data with the server — WITHOUT reloading the entire page.

  • Creates "rich" web interfaces that respond instantly without full page reload.
  • Uses: XMLHttpRequest object (XHR) or Fetch API in JavaScript.
  • Data formats: JSON (modern), XML (original).
  • Examples: Google search auto-suggestions, Gmail inbox real-time updates, Facebook Like button without page refresh.
  • Cloud use: AJAX calls REST APIs to fetch/update cloud data dynamically.
⭐

Mashup = combining multiple cloud APIs into one app. AJAX = updating page without full refresh. AJAX is the technology that makes cloud mashups work smoothly in browser. Classic example: Google Maps embedded in another website.

✏️ Cloud Mashups leverage the power of multiple cloud APIs to build innovative applications rapidly. AJAX enables these mashups to provide smooth, real-time, rich user interfaces without disruptive page reloads.

Q11. What virtualization support is needed for fast VM cloning? How does VM cloning enable fast recovery? Explain VMware and vSphere.
5 Marks7 Marks
VM Cloning — Definition

VM Cloning is the process of creating an identical copy of an existing virtual machine (including OS, applications, and data configuration). The clone is an independent VM that can run immediately.

Virtualization Support for Fast Cloning
  • Copy-on-Write (COW): Instead of copying all data, clone initially shares the same storage blocks. New blocks are only created when data is modified. This makes cloning nearly instantaneous.
  • Snapshot Support: Hypervisor must support instant VM snapshots (freeze state) from which clones are created.
  • Thin Provisioning: Clones use only the storage they actually need, not the full allocated space — enabling faster deployment.
  • Linked Clones: Clone references parent VM's disk snapshot; only differences are stored — small size, instant creation.
  • Full Clones: Complete independent copy of VM — larger, but fully independent from parent.
VM Cloning for Fast Recovery
  • Create a golden image (master VM) of a properly configured server.
  • If a server fails, clone the golden image → deploy the clone in minutes.
  • No OS installation or application setup needed — immediate recovery.
  • Cloud auto-scaling uses cloning to deploy additional servers during high load.
VMware vSphere — Overview

VMware vSphere is VMware's enterprise cloud computing virtualization platform. It includes:

  • ESXi: Type-1 bare-metal hypervisor that runs VMs directly on hardware.
  • vCenter Server: Centralized management for multiple ESXi hosts and VMs.
  • vSphere Client: Web interface to manage VMs, storage, networking.
  • vMotion: Live migration of running VMs between ESXi hosts without downtime.
  • High Availability (HA): Automatically restarts VMs on another host if the current host fails.
  • DRS: Distributed Resource Scheduler — automatically balances VM workloads across hosts.
⭐

VM Cloning key: COW (Copy-on-Write) makes it fast. Linked clone = references parent snapshot. Full clone = independent copy. VMware vSphere = ESXi + vCenter — mention vMotion as a key feature.

✏️ VM cloning using Copy-on-Write and linked clones enables near-instant VM deployment, making it the foundation of cloud auto-scaling and fast disaster recovery — allowing organizations to restore services in minutes rather than hours.

GFS — Google File System

GFS (Google File System) is a scalable distributed file system developed by Google for large-scale data-intensive applications. It was designed to run on commodity hardware and handle petabytes of data reliably.

GFS Architecture
Google File System Architecture

  • Master Server: Maintains ALL metadata — file names, chunk locations, access control. Single master design (simple but potential bottleneck).
  • Chunk Servers: Store actual data in 64MB fixed-size chunks. Each chunk replicated 3× on different servers for fault tolerance.
  • Client: Asks master for chunk location → then directly reads/writes to chunk servers.
  • Fault Tolerance: 3× replication of every chunk. Master monitors chunk servers via heartbeats.
  • Optimized for: Large files (GB-TB range), streaming reads, append operations. NOT for random small reads/writes.
HDFS — Hadoop Distributed File System

HDFS (Hadoop Distributed File System) is an open-source distributed file system (part of Apache Hadoop) inspired by GFS. It is designed to run on commodity hardware and store very large files reliably for big data processing.

MapReduce — Definition

MapReduce is a programming model and processing framework for parallel processing of large datasets across a distributed cluster of commodity computers. Developed by Google (2004). Open-source implementation is Hadoop MapReduce.

Core Idea: Break a big problem into small sub-problems, solve each in parallel (Map phase), then combine the results (Reduce phase). Like dividing a big book among 100 readers to count words — then summing up their individual counts.

Phase-wise Explanation
  • Input Phase: Data is read from HDFS and divided into fixed-size input splits (typically 128MB = one HDFS block).
  • Map Phase: Each Map task processes one input split. Takes (key, value) pairs as input, produces intermediate (key, value) pairs as output. Example: For word count, each line is a key-value; mapper outputs (word, 1) for each word.
  • Shuffle & Sort Phase: All intermediate key-value pairs with the SAME key are grouped together and sent to the same Reducer. This is the most network-intensive phase — data moves across nodes.
  • Reduce Phase: Each Reduce task receives all values for a given key and aggregates them. Example: Receives ("cloud", [1,1,1,1]) → outputs ("cloud", 4).
  • Output Phase: Final results written back to HDFS.

Virtual Threats

Virtual Threats are security threats specific to virtualized cloud environments. They exploit vulnerabilities in hypervisors, VMs, and virtual networking.

Types of Virtual Threats
  • VM Escape: Most dangerous — attacker breaks out of a VM and gains access to the hypervisor or host OS, then controls ALL VMs on that host.
  • VM Sprawl: Unmanaged VMs — old, forgotten VMs with outdated software become attack entry points.
  • Hyperjacking: Attacker installs a rogue hypervisor below the legitimate hypervisor — gains complete control invisibly.
  • VM Hopping: Attacker moves from one VM to another VM on the same physical host by exploiting network vulnerabilities.
  • Snapshot/Image Theft: Stealing VM images (OVF files) gives attacker a copy of the entire VM with all its data.
  • Guest-to-Guest Attack: VMs on same host attack each other through shared memory channels.
  • DoS on Hypervisor: Flooding hypervisor with requests — crashes all VMs on the host.
VM Security Techniques
  • VM Isolation: Strict isolation between VMs — separate virtual networks, memory protection.
  • Regular Patching: Keep hypervisor and guest OS patched against known vulnerabilities.
  • VM Image Hardening: Remove unnecessary services, close unused ports before deploying VM images.
  • Encrypted VM Storage: VM disks encrypted using AES-256 to prevent image theft.
  • Intrusion Detection (HIDS/NIDS): Host-based and network-based intrusion detection systems in each VM.
  • Secure Live Migration: Encrypt VM data during live migration (vMotion encryption).
  • Access Control: Only authorized admins can manage VMs — RBAC (Role-Based Access Control).
  • VM Lifecycle Management: Decommission unused VMs promptly to prevent VM sprawl.
  • Network Segmentation: Put VMs in separate VLANs — limit lateral movement of attackers.
— Trusted Cloud Computing —
Trusted Cloud Computing

Trusted Cloud Computing refers to a cloud environment where users can reliably trust that their data, computations, and privacy are protected — even from the cloud provider itself. Built on hardware-level security.

  • Trusted Platform Module (TPM): Hardware chip that stores cryptographic keys securely — ensures hardware integrity.
  • Intel TXT (Trusted Execution Technology): Measures and verifies the integrity of hypervisor at boot time.
  • Secure Enclaves: Intel SGX — encrypted memory regions where sensitive computations run, invisible even to the OS.
  • Remote Attestation: Cloud provider proves to customer that the correct, unmodified software is running.
⭐

VM threats: VM Escape (most serious!), VM Sprawl, Hyperjacking. Security: patch regularly, encrypt VM disks, isolate networks, RBAC. Trusted cloud = TPM + Intel TXT + secure enclaves for hardware-level trust.

✏️ Virtualization introduces unique security threats not found in traditional computing. Addressing virtual threats requires a combination of hypervisor hardening, VM isolation, encrypted storage, and hardware-based trust mechanisms.

Data Access Control ensures that only authorized users, applications, and services can access sensitive data in cloud environments. It is enforced through identity management and access control policies.

Q18. What do you understand by Secure Communication in Cloud? How is it achieved?

Secure Communication in Cloud

Secure Communication in cloud refers to protecting data while it is transmitted between cloud clients, services, and servers — preventing eavesdropping, tampering, and man-in-the-middle attacks.

How Secure Communication is Achieved
  • TLS/SSL (Transport Layer Security): Encrypts all data in transit using symmetric encryption (AES) + asymmetric key exchange (RSA/ECDH). HTTPS = HTTP + TLS. All cloud APIs use TLS 1.2/1.3.
  • VPN (Virtual Private Network): Creates an encrypted tunnel between user/enterprise and cloud. IPsec VPN for site-to-site, SSL VPN for remote users. Example: AWS VPN, Azure VPN Gateway.
  • IPsec: Internet Protocol Security — encrypts and authenticates IP packets at network layer. Used in site-to-site VPN connections.
  • SSH (Secure Shell): Encrypted terminal access to cloud VMs. All VM administration should use SSH (not Telnet).
  • Digital Certificates (PKI): Public Key Infrastructure — certificates verify server identity, prevent impersonation. Issued by trusted Certificate Authorities (CA).
  • API Keys & OAuth 2.0: Secure authentication for API calls between cloud services — prevents unauthorized API access.
  • End-to-End Encryption (E2EE): Data encrypted from sender to receiver — even the cloud provider cannot read it.
⭐

Secure communication = TLS for data in transit + VPN for network tunneling + SSH for VM access + PKI for identity verification. The trinity: Encryption + Authentication + Integrity. TLS = most important answer point.

✏️ Secure communication in cloud is achieved through a combination of encryption protocols (TLS, IPsec), VPN tunnels, and PKI-based authentication — ensuring data confidentiality, integrity, and authenticity across all cloud communications.

Load Balancing Algorithms
  • Round Robin: Requests distributed to servers in rotation. Simple, works well for equal capacity servers.
  • Least Connections: Send request to server with fewest active connections — better for varying request lengths.
  • IP Hash: Client IP determines which server handles request — maintains session affinity (sticky sessions).
  • Weighted Round Robin: More powerful servers get proportionally more requests (weight-based distribution).
  • Resource-Based: Route to server with most available CPU/RAM — dynamic, intelligent distribution.
QoS Issues in Cloud Computing

Quality of Service (QoS) in cloud refers to ensuring cloud services meet defined performance standards (SLA — Service Level Agreement).

  • Response Time: Delay in responding to user requests — network latency, server load issues.
  • Availability: Ensuring uptime as per SLA (99.9%, 99.99%). Downtime = financial/reputational loss.
  • Throughput: Amount of data processed per unit time — bandwidth limitations affect throughput.
  • Scalability: System must handle increasing load without degradation — auto-scaling failures.
  • Reliability: Consistent performance — avoiding intermittent failures.
  • Security QoS: Security mechanisms (encryption, authentication) should not unacceptably degrade performance.
Case Study: E-Commerce Load Balancing
Scenario: Amazon during Big Sale (Prime Day) gets 10× normal traffic.
Solution: AWS Auto Scaling + Elastic Load Balancer (ELB):
1. ELB receives all incoming traffic and distributes using Round Robin.
2. CloudWatch monitors CPU — when CPU > 70%, Auto Scaling adds new EC2 instances.
3. When traffic reduces, instances are automatically terminated (scale-in).
4. Result: Zero downtime, optimal performance, pay only for actual usage.

  • SLA Compliance: Real-time uptime monitoring ensures 99.9% availability commitments are met.
  • Cost Optimization: Identify idle/underutilized resources — terminate or downsize to save costs.
  • Root Cause Analysis: Monitoring logs help trace the cause of performance degradation or failures.
