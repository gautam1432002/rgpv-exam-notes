1.1 Definition and Introduction to IoT
5 Marks7 Marks10 Marks
Definition

Internet of Things (IoT) is defined as a network of physical objects (things) embedded with sensors, software, and other technologies that connect and exchange data with other devices and systems over the internet.

Simple Definition: IoT = Physical World + Internet. It means connecting everyday physical objects (like bulbs, fans, fridges, cars) to the internet so they can send and receive data automatically — without needing a human to operate them.
Explanation

The term "Internet of Things" was coined by Kevin Ashton in 1999. In traditional internet, humans interact with digital content. In IoT, machines/devices interact with each other (M2M) and with humans through the internet.

Example: A smart thermostat reads room temperature (sensor), sends data to the cloud, which then decides to turn on/off the AC (actuator) — all automatically.

Characteristics of IoT
  • Connectivity: All IoT devices must be connected to the internet or a network.
  • Intelligence (Smart Behavior): IoT devices can sense, analyze, and respond.
  • Dynamic Nature: Devices change their state (active/passive) automatically.
  • Enormous Scale: Billions of devices worldwide are connected (50 billion by 2030).
  • Self-Configuring: IoT devices can configure themselves when connected to a network.
  • Interoperability: Different devices from different companies can work together.
  • Sensing: IoT devices collect real-world data using sensors.
  • Energy Efficiency: IoT devices are designed to consume very low power.
  • Security: Data exchanged must be protected from unauthorized access.
  • Integration: IoT integrates physical and digital worlds seamlessly.
Applications
  • Smart Home (Alexa, Google Home)
  • Smart Healthcare (patient monitoring)
  • Smart Agriculture (soil sensors, irrigation)
  • Smart Cities (traffic management, waste management)
  • Industrial IoT / Industry 4.0
  • Smart Vehicles / Connected Cars
Important Points for Exam
⭐

Kevin Ashton coined "IoT" in 1999. RFID was the first IoT technology. IoT = Sensors + Connectivity + Data Processing. The 3 pillars of IoT are: Sensing, Processing, and Communication.

✏️ IoT is the backbone of modern digital transformation. It connects billions of physical devices to the internet, enabling smart automation and data-driven decision-making across all sectors of life.

1.4 Physical and Logical Design of IoT
7 Marks10 Marks
Introduction

IoT system design is divided into two parts — Physical Design (hardware and connectivity) and Logical Design (software and functional model).

Physical Design of IoT

Physical design refers to the hardware components of an IoT system and how they are physically connected.

  • IoT Devices/Things: Smart objects with embedded sensors, processors (microcontrollers), and communication modules.
  • Communication Networks: The physical wired or wireless links connecting devices.
  • IoT Gateways: Physical hardware that aggregates data from devices.
  • Cloud/Server Infrastructure: Physical servers or cloud hardware where data is stored and processed.
Logical Design of IoT

Logical design defines the functional behavior and architecture — how data flows, how processes are organized, and how services interact.

1.5 IoT Enablers
5 Marks
Definition

IoT Enablers are the key technologies and innovations that have made IoT possible and practical. Without these, IoT as we know it today would not exist.

Key IoT Enablers
  • RFID (Radio Frequency Identification): Allows unique identification of objects using radio waves — the original IoT technology.
  • Wireless Sensor Networks (WSN): Network of small, low-power sensors that collect and transmit environmental data.
  • IPv6 (Internet Protocol v6): Provides virtually unlimited IP addresses (3.4×10³⁸) to connect billions of IoT devices.
  • Cloud Computing: Provides scalable storage, processing, and analytics for massive IoT data.
  • Big Data & Analytics: Enables extracting useful insights from the huge volumes of IoT data.
  • Miniaturization of Hardware: Advances in chip design make powerful microcontrollers very small and cheap.
  • Machine Learning / AI: Allows IoT systems to make intelligent autonomous decisions.
  • 5G Networks: Ultra-fast, low-latency communication for massive IoT deployments.
  • Edge Computing: Allows processing near the device, reducing latency and bandwidth usage.
  • Low-power Communication (ZigBee, LoRa): Enables battery-operated IoT devices to run for months or years.
⭐

Remember the top 5 enablers: RFID, WSN, IPv6, Cloud Computing, and Miniaturization of Hardware. These are most commonly asked in 5-mark questions.

1.10 IoT Network Configurations — LAN, WAN, Node, Gateway, Proxy
5 Marks7 Marks10 Marks
Introduction

IoT devices are organized and connected through specific network configurations. Understanding these is essential for designing scalable IoT systems.

IoT LAN (Local Area Network)
IoT LAN is a network that connects IoT devices within a small, limited area such as a home, office, or factory floor. It uses protocols like WiFi, Bluetooth, ZigBee, Z-Wave.
Example: All smart devices in a smart home connected to a home router.
IoT WAN (Wide Area Network)
IoT WAN connects IoT devices over large geographical areas — cities, countries, or globally. It uses protocols like LoRaWAN, NB-IoT, LTE-M, Sigfox, cellular networks.
Example: Agricultural sensors across thousands of farms sending data to a central cloud server.
IoT Node
An IoT Node is the most basic unit of an IoT network — a single device with a sensor/actuator, a microcontroller/processor, and a communication module. It is the "end device" in the IoT network.
Example: A temperature sensor on a factory floor = one IoT node.
IoT Gateway
An IoT Gateway is a hardware device that acts as a bridge between IoT nodes and the cloud/internet. It performs:
• Protocol Translation — converts ZigBee → WiFi → Internet
• Data Aggregation — combines data from multiple sensors
• Local Processing (Edge) — filters and pre-processes data before sending to cloud
• Security — acts as first line of defense
Example: Amazon Echo Hub, Industrial IoT Gateway by Cisco
IoT Proxy
An IoT Proxy is an intermediary device or software that acts on behalf of an IoT device when the device cannot directly communicate with the network. The proxy receives requests, processes them, and forwards them to the actual device.
Example: A constrained sensor with no IP address uses a proxy to communicate over the internet.

2.1 Sensor — Definition, Components, and Challenges
5 Marks7 Marks10 Marks
Definition of Sensor

A Sensor is a device that detects or measures a physical quantity (such as temperature, pressure, light, humidity) and converts it into an electrical signal that can be processed by a computer or microcontroller.

Simple Definition: Sensor = Input Transducer. It converts real-world physical signals → electrical signals. Example: Thermometer converts temperature → voltage reading.

Components Explained
  • Sensing Element: The actual transducer that detects the physical quantity (e.g., thermistor in a temp sensor).
  • Signal Conditioning Circuit: Amplifies and filters the raw sensor signal to make it usable.
  • ADC (Analog-to-Digital Converter): Converts analog electrical signal to digital form for microcontroller.
  • Microcontroller/Processor: Processes sensor data — applies calibration, filtering, and decision-making.
  • Memory: Stores sensor readings, calibration data, and firmware.
  • Communication Module: Transmits processed data via WiFi, ZigBee, BT to gateway/cloud.
  • Power Supply: Battery or energy harvesting (solar, vibration) to power the sensor node.
Challenges of Sensor Nodes
  • Limited Energy: Battery-operated — energy efficiency is critical. Must last months/years.
  • Limited Processing Power: Tiny MCUs cannot run complex algorithms.
  • Limited Memory: Very small RAM and Flash storage.
  • Communication Range: Short communication range requires relay/mesh networks.
  • Environmental Exposure: Sensors deployed outdoors face heat, humidity, and dust.
  • Data Accuracy: Calibration drift over time affects measurement accuracy.
  • Security: Constrained devices cannot run heavy encryption algorithms.
  • Cost: Must be cheap enough for mass deployment.

✏️ Sensors are the foundation of any IoT system. Despite their small size, they face significant technical challenges. Efficient design and energy management are the core concerns in sensor node development.

Sensor Resolution — Detailed

Sensor Resolution is the smallest change in the measured quantity that the sensor can detect and report. It determines how "fine-grained" the measurements are.

Resolution Formula:
Resolution = Full Scale Range / 2ⁿ
Where n = number of bits in the ADC.
Example: A 12-bit ADC measuring 0–5V: Resolution = 5V / 2¹² = 5/4096 ≈ 1.22 mV
  • Higher resolution → More bits in ADC → Finer measurements
  • 8-bit ADC: 256 levels; 12-bit ADC: 4096 levels; 16-bit ADC: 65536 levels
  • Resolution is different from accuracy — a sensor can have high resolution but low accuracy

2.4 Sensor Errors — Bias, Drift, Hysteresis, Quantization
5 Marks7 Marks10 Marks
Sensor Bias
Bias is a constant systematic error where the sensor output is consistently offset from the true value by a fixed amount. It is also called "offset error."
Example: A temperature sensor always reads 2°C higher than actual → Bias = +2°C
Fix: Calibration (subtract the bias value from all readings)
Sensor Drift
Drift is a gradual change in sensor output over time even when the input quantity remains constant. Drift is caused by aging of components, temperature changes, humidity, etc.
Types:
• Zero Drift: The zero point of the sensor shifts over time
• Span Drift: The full-scale output changes over time
Example: A pressure sensor in a factory reads slightly different values each month even when measuring the same pressure.
Hysteresis Error
Hysteresis Error occurs when a sensor gives different output values for the same input depending on whether the input is increasing or decreasing. The sensor has "memory" of past states.
Example: When temperature increases from 20°C to 50°C, the sensor reads 25°C at input 25°C. But when temperature decreases from 50°C to 20°C, the sensor reads 27°C at input 25°C → Hysteresis = 2°C
Common in: Magnetic sensors, pressure sensors, mechanical sensors
Quantization Error
Quantization Error is the error introduced when a continuous analog signal is converted to a discrete digital value by an ADC. The original signal cannot be represented exactly — it is rounded to the nearest digital level.
Formula: Quantization Error = ±(Resolution/2) = ±(FSR / 2^(n+1))
Example: For a 3-bit ADC measuring 0–8V:
Resolution = 8/8 = 1V. Quantization Error = ±0.5V
A value of 2.7V would be stored as 3V — Error = 0.3V

2.5 Actuator — Definition and Types
5 Marks7 Marks10 Marks
Definition of Actuator

An Actuator is a device that converts an electrical signal (or other energy form) into a physical action or movement. While sensors are inputs, actuators are outputs — they make things happen in the physical world.

Simple Analogy: Sensor = Eyes of IoT (collects information). Actuator = Hands/Muscles of IoT (takes action). Example: Temperature sensor detects high temp → actuator (cooling fan) switches on.
Types of Actuators

1. Hydraulic Actuators

  • Use pressurized hydraulic fluid to produce mechanical motion
  • Capable of producing very high forces and torque
  • Used in heavy machinery, construction equipment, aircraft landing gear
  • Advantage: Very high force output, precise control
  • Disadvantage: Fluid leakage risk, bulky, requires maintenance
  • IoT Use: Industrial automation, heavy robotic arms

2. Pneumatic Actuators

  • Use compressed air or gas to produce linear or rotary motion
  • Lighter and faster than hydraulic actuators
  • Used in manufacturing assembly lines, valve control, packaging
  • Advantage: Fast, clean (no fluid), low maintenance
  • Disadvantage: Lower force than hydraulic, air compressor required
  • IoT Use: Smart manufacturing, automated doors

3. Electrical Actuators

  • Convert electrical energy into mechanical movement using motors or solenoids
  • Most common actuator type in IoT systems
  • Sub-types: DC motors, Stepper motors, Servo motors, Solenoid valves, Relays
  • Advantage: Easy to control with microcontrollers, precise, efficient
  • Disadvantage: Cannot produce as high force as hydraulic
  • IoT Use: Smart locks, robotic systems, home automation

4. Thermal / Magnetic Actuators

  • Thermal Actuators: Use shape-memory alloys or bi-metallic strips that deform when heated. Used in thermostats and HVAC.
  • Magnetic Actuators (Electromagnets): Use magnetic fields to produce mechanical force. Used in solenoids, maglev systems, MRI machines.
  • Advantage: Silent operation, no moving parts in some designs
  • IoT Use: HVAC control valves, electromagnetic door locks

5. Mechanical Actuators

  • Convert rotary motion into linear motion using mechanical components (gears, screws, levers, cams)
  • Examples: Lead screw, rack and pinion, cam follower
  • Advantage: Simple, reliable, no fluid required
  • IoT Use: Linear actuators for solar panel positioning, automated window openers

6. Soft Actuators

  • Made of soft, flexible materials (silicone, hydrogels, shape-memory polymers)
  • Can perform gentle, compliant movements — safe for human interaction
  • Inspired by biological muscles
  • Advantage: Flexible, safe for human contact, adaptable to irregular shapes
  • IoT Use: Medical robotics, wearable devices, soft robotic grippers

3.1 Basics of IoT Networking and IoT Service-Oriented Architecture
5 Marks7 Marks
IoT Networking Basics

IoT Networking refers to the technologies, protocols, and infrastructure that allow IoT devices to communicate with each other, with gateways, and with cloud platforms.

Key Requirements of IoT Networks
  • Low Power: Devices must operate for years on batteries
  • Low Cost: Chips and modules must be affordable for mass deployment
  • Low Data Rate: Most IoT data is small packets (temperature = few bytes)
  • Long Range: Some applications need kilometers of coverage (agriculture)
  • High Device Density: Must support millions of devices per km²
  • Security: End-to-end encryption and authentication
  • Reliability: Data must be delivered even in noisy RF environments
IoT Service-Oriented Architecture (SOA)

IoT Service-Oriented Architecture treats every IoT capability (sensing, actuation, storage) as a service that can be accessed by other components over a network using standard interfaces.

IoT Service-Oriented Architecture

↕
🌐 Network Layer — IP-based Communication, IoT Middleware
↕
📡 Device Layer — Sensors, Actuators, RFID, Smart Devices
  • Service Discovery: Devices register and discover services dynamically
  • Service Composition: Complex applications built by combining multiple IoT services
  • Loose Coupling: Services are independent — change one without breaking others
  • Reusability: A sensor service can be used by multiple applications

3.3 6LoWPAN (IPv6 over Low-Power Wireless Personal Area Networks)
5 Marks7 Marks10 Marks
Definition

6LoWPAN stands for IPv6 over Low-Power Wireless Personal Area Networks. It is an adaptation layer that allows IPv6 packets to be transmitted over IEEE 802.15.4 low-power wireless networks by compressing and fragmenting IPv6 headers.

Why is 6LoWPAN Needed?
Problem: IPv6 packet headers are 40 bytes minimum. IEEE 802.15.4 (the physical layer) supports max frame size of only 127 bytes. After subtracting other headers, only ~80 bytes are available for data payload. A standard IPv6 header (40 bytes) would take up half the frame!
Solution: 6LoWPAN compresses the IPv6 header from 40 bytes down to as few as 2 bytes, making IPv6 feasible for low-power IoT devices.
Features of 6LoWPAN
  • Header Compression: Reduces IPv6 header to 2–7 bytes using IPHC (IP Header Compression)
  • Fragmentation & Reassembly: Splits large IPv6 packets into small 802.15.4 frames
  • Mesh Addressing: Supports multi-hop routing in mesh networks
  • Works on IEEE 802.15.4: Physical and MAC layer standard for low-power wireless
  • Enables End-to-End IPv6: IoT devices can directly communicate using IPv6 addresses
  • Low Power: Designed for battery-operated devices
  • Defined by: IETF RFC 4944 (original) and RFC 6282 (header compression)
6LoWPAN in Protocol Stack

4.1 MQTT — Message Queuing Telemetry Transport
5 Marks7 Marks10 Marks
Definition

MQTT (Message Queuing Telemetry Transport) is a lightweight, publish-subscribe messaging protocol designed for constrained IoT devices and low-bandwidth, high-latency networks. It runs over TCP/IP and is ideal for machine-to-machine communication.

Key Idea: MQTT uses a Pub-Sub model — devices do NOT communicate directly. A central Broker receives messages from publishers and forwards them to all interested subscribers.
MQTT Components
  • Publisher (Client): An IoT device that produces/sends data. It publishes messages to a topic. Example: Temperature sensor publishes to topic "home/bedroom/temperature".
  • Broker (Server): The central intermediary. Receives all published messages and routes them to appropriate subscribers. Example: Mosquitto Broker, AWS IoT Core, HiveMQ.
  • Subscriber (Client): An application or device that wants to receive data. It subscribes to a specific topic. Example: A smartphone app subscribes to "home/bedroom/temperature" to display readings.
  • Topic: A hierarchical string used to categorize messages. Allows wildcards (# and +). Example: "factory/machine1/temperature".

MQTT Features
  • Very lightweight — minimum 2-byte fixed header
  • Runs over TCP/IP — reliable delivery
  • Supports Last Will and Testament (LWT) — broker notifies others if a client disconnects unexpectedly
  • Supports Retained Messages — broker saves last message on a topic for new subscribers
  • Supports persistent sessions for offline clients
  • Default port: 1883 (unencrypted), 8883 (TLS/SSL encrypted)
Advantages
  • Extremely lightweight — works on 8-bit microcontrollers with very little RAM
  • Works well on unreliable, high-latency networks
  • Scalable — one broker can handle thousands of clients
  • Flexible QoS levels for different reliability needs
Disadvantages
  • Requires always-on broker — single point of failure
  • Basic security in early versions (no built-in encryption in MQTT 3.1)
  • Not suitable for request-response communication (like HTTP)
Applications of MQTT
  • Smart home automation (sending sensor data)
  • Facebook Messenger (used MQTT for mobile notifications)
  • AWS IoT, Microsoft Azure IoT Hub
  • Industrial IoT machine monitoring
  • Vehicle telematics

✏️ MQTT's lightweight nature, flexible QoS levels, and publish-subscribe model make it the most widely used messaging protocol in IoT applications worldwide.

4.2 SMQTT (Secure MQTT)
5 Marks
Definition

SMQTT (Secure MQTT) is an extension of the standard MQTT protocol that adds a security layer using broadcast encryption to protect IoT data. It provides attribute-based encryption to ensure that only authorized subscribers can decrypt messages.

SMQTT Working — 4 Phases
  • Setup Phase: Master key is generated and distributed. Each subscriber gets a unique attribute-based key based on their permissions.
  • Encrypt Phase: Publisher encrypts the message using a broadcast encryption scheme. Only subscribers with matching attributes can decrypt it.
  • Publish Phase: Encrypted message is published to the broker on a topic (same as MQTT).
  • Decrypt Phase: Authorized subscriber receives the message and decrypts it using their attribute key.

4.4 XMPP (Extensible Messaging and Presence Protocol)
5 Marks
Definition

XMPP (Extensible Messaging and Presence Protocol) is an open-standard XML-based protocol for real-time messaging, presence information (online/offline status), and request-response services. Originally developed for instant messaging (Jabber).

4.5 AMQP — Advanced Message Queuing Protocol
5 Marks7 Marks10 Marks
Definition

AMQP (Advanced Message Queuing Protocol) is an open, wire-level messaging protocol for enterprise and IoT messaging. It provides reliable message queuing, flexible routing, transactions, and security. Defined by ISO/IEC 19464.

Key Difference from MQTT: AMQP is more feature-rich and heavyweight. It is designed for enterprise-level, broker-based messaging where reliability, transactions, and complex routing are needed. MQTT is simpler; AMQP is more powerful.
AMQP Components
  • Producer (Publisher): Application that creates and sends messages.
  • Broker: Central server with Exchanges and Queues. Routes messages. Example: RabbitMQ, Apache ActiveMQ.
  • Exchange: Receives messages from producers and routes them to queues based on routing rules (binding keys).
  • Queue: Buffer that stores messages until they are consumed by a consumer.
  • Consumer (Subscriber): Application that receives messages from queues.
  • Binding: Rule that links an exchange to a queue with a routing key.
  • Virtual Host (vHost): Logical grouping of resources for isolation.
  • Channel: Lightweight connection within a TCP connection. Multiple channels share one TCP connection.

5.6 Security in IoT — Attacks and Vulnerability Analysis
5 Marks7 Marks10 Marks
IoT Security Overview

IoT security is one of the biggest challenges in IoT deployment. Due to the resource-constrained nature of IoT devices (low power, limited memory), implementing strong security is difficult. This makes IoT devices attractive targets for attackers.

Common Attacks on IoT Systems
Attack TypeDescriptionTargetExample
DoS / DDoS AttackFlood device/server with requests to make it unavailableIoT server, cloudMirai Botnet — used IoT cameras for massive DDoS attack (2016)
Man-in-the-Middle (MITM)Attacker intercepts communication between devicesNetwork trafficIntercepting unencrypted MQTT messages
EavesdroppingPassive listening to IoT network trafficWireless communicationSniffing ZigBee/WiFi packets
Replay AttackRe-sends captured packets to repeat authorized actionsAuthenticationReplaying a door unlock command
Firmware AttackInject malicious code into IoT device firmwareDevice softwareMalicious OTA (Over-The-Air) update
Physical AttackTamper with IoT device hardware directlyPhysical deviceExtracting encryption keys from circuit boards
Brute ForceTry all possible passwords to gain accessAuthenticationGuessing default admin:admin credentials
Sybil AttackAttacker creates multiple fake identities in networkWSN / IoT networkFake sensor nodes injecting false data
Vulnerability Analysis in IoT

Vulnerability analysis is the process of identifying, classifying, and prioritizing weaknesses in IoT systems before attackers can exploit them.

  • Insecure Network Services: Open ports, unencrypted protocols (Telnet, HTTP without TLS)
  • Weak Authentication: Default passwords (admin/admin), no multi-factor auth
  • Insecure Update Mechanism: No firmware signature verification — allows malicious OTA updates
  • Use of Outdated Components: Old libraries with known vulnerabilities
  • Insecure Data Storage: Storing passwords or keys in plain text on device
  • Lack of Physical Security: Exposed debug ports (JTAG, UART) on production devices
  • Privacy Issues: IoT devices collecting more data than necessary
  • Insufficient Logging: Attacks are not detected because no logs are maintained
IoT Security Best Practices
  • Use TLS/SSL for all communication (MQTT over TLS, HTTPS)
  • Change default credentials immediately after deployment
  • Keep firmware updated with signed OTA updates
  • Use device certificates (X.509) for authentication
  • Network segmentation — isolate IoT devices on separate VLAN
  • Encrypt sensitive data at rest on device storage
  • Disable unused services and close unnecessary ports
  • Regular penetration testing of IoT systems
⭐

Mirai Botnet (2016) is the most famous real-world IoT attack — it used default credentials on IP cameras to create a massive DDoS botnet. OWASP IoT Top 10 vulnerabilities list is important. Most asked: DoS, MITM, Firmware Attack, Sybil Attack definitions + countermeasures.
